# Agent Note: Codex CLI as a Harness reasoning provider

Status: implemented

[English](2026-09-09-codex-brain.md) | 中文

## 问题

用户已有通过 ChatGPT 认证的本机 Codex，希望将其用于普通 Harness 对话，同时继续手动使用 Codex。

## 决策

`llm-codex` 插件提供普通 LLM 适配器和经过认证的管理服务。官方 CLI 执行负责认证。严格 JSON 响应携带文本与请求的 Harness 工具调用；现有 Harness 循环执行工具并记录结果。设置页管理配置、安装检测、连接测试、默认选择和单请求先进先出队列。

CLI 在临时私有目录中运行，忽略用户配置并关闭原生工具。持久化用户图片通过附件服务解析，转换为有限大小的请求版本，在该目录中生成文件，再使用官方 `--image` 参数按序号附加。JSON 历史保留每张图片所属的用户消息。所属进程退出后删除图片文件；队列元数据不包含提示词、图片字节或路径。取消仅针对所持有的进程树。队列元数据持久化；重启后未完成记录变为中断。适配器不读取或复制令牌、Cookie 或密码。此功能不替代现有 Codex 子智能体后端。

## 考虑过的替代方案

**使用复制的 OAuth 凭据调用私有接口。** 否决，因为认证与账号访问必须由官方客户端负责。

**通过现有 Codex 子智能体后端委托整段对话。** 这会让 Codex 执行自己的工具，绕过此处要求的普通 Harness 对话和工具循环。

**在整个 Harness 回合期间占用队列执行槽。** 等待嵌套智能体的父智能体可能持有子智能体所需的唯一执行槽。逐请求串行避免这一死锁，并允许对话在工具轮次之间交替进行。

## 影响

用户保留手动 Codex 会话并共享订阅登录。适配器增加完整上下文序列化、保留的图片输入和逐请求进程启动延迟。输出完整验证后的回复而非逐 token 流式输出。图片历史有上限；较早的出现位置会变成文字占位符，非用户图片历史会明确失败。独立主机进程不协调队列。不暴露剩余额度或金额估算。协议和进程测试覆盖错误输出、先进先出执行、图片转换与清理、取消、超时、限流暂停与无关进程存活；可选官方 CLI 测试验证真实认证和响应传输。浏览器验收覆盖实际组合、真实文件读取工具闭环和真实图片请求。
